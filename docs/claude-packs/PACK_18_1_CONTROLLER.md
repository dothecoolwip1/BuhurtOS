Status: **built and tested at stand-in level. NOT verified against real OBS.** Branch `worktree-agent-a325bfb422f0fc647` (see the end for the base it was built on). Nothing here was deployed, pushed, merged or applied to hosted Supabase.

### 1.1 The AUTO decision (`decide.ts`)
Per-field input is the Pack 14 `SceneMode` from `broadcastScene` (never re-derived) plus a durable first-live time. Phases: fightLive = live, paused, break, equipment, dq_clock, disqualified; armed = ready, intro; post = complete, winner; quiet = idle, upcoming, between. Rules in order: Camera Off (server OR local latch; unknown server state keeps a last-known Off) beats everything; manual beats auto; the AUTO lock stays through every fightLive/post phase and releases only at quiet, on a different fight on that Lyst, or when a finished fight is shown as in progress again (reopened); pick next = earliest first-live, ties by the organizer's priority list then field key, else earliest armed (same ties), else holding; 10 s minimum between AUTO switches (never delays Camera Off, an operator's choice or Return to Auto); a Lyst just left cannot be re-taken for 5 s (in practice the 10 s dwell already covers it); "also live" list; Return to Auto is a fresh decision (no lock, no dwell, no replay). Output: target `{kind, field}`, the mapped scene (or a mapping problem: a mapped scene missing in OBS falls back to holding; no holding scene keeps the current scene and reports; an unmapped Lyst is never taken and is reported; a missing Camera Off scene falls back to holding and asks the caller to mute the camera audio), lock, also-live, reason words, and the state to hand back on the next call. 42 vector tests.

### 1.2 The Companion
* **OBS client** (`src/obs/client.ts`): obs-websocket v5 handshake (`secret = base64(sha256(password + salt))`, `auth = base64(sha256(secret + challenge))`), loopback only (anything but 127.0.0.1 / ::1 / localhost is refused at construction), backoff 1, 2, 5, 10 s then every 10 s for ever, requests with timeouts, events. Subscriptions Scenes | Inputs | Outputs | General | Filters | MediaInputs, plus the meter bit only when a microphone is configured.
* **Allow-list** (`src/obs/allowlist.ts`): 19 request types, default deny, checked in the client before anything touches the socket; every request in a batch is checked first and one refusal refuses the batch. Mute / volume / filter / media requests are further restricted to the configured music source, the one ducking filter on it, and the one Media Source (play and pause only). `ws.send` exists in exactly two places in `client.ts` (a test greps for it). A test also asserts no forbidden request name appears anywhere in the source or in the built bundle.
* **Controller session** (`src/session.ts`): signs in at `/functions/v1/device-session` (`signin`), keeps the session secret in the credential store, refreshes the token ~90 s before expiry, tolerates outages (keeps what is valid, retries), backs off a refused code (30 s doubling to 5 min) instead of hammering. Without a code the Companion still runs AUTO from public data.
* **State reader** (`src/reader.ts`, `src/scenes.ts`): polls every 2.5 s (backoff to 10 s, never overlapping) the same public data the overlay uses via the app's own modules (`fetchEvent`, `fetchCompetitionMatches`, `fetchLiveScores`, `fetchLystPublic`, `buildArena`, `broadcastScene`) plus `controller_state()`. First-live times come from `lyst_rounds` (round 1 `created_at`, public for a public event) and are kept in the local file. Scenes are rebuilt from the last good data every second, so the 8 s / 25 s result windows keep counting while offline. A failed Camera Off read is "unknown", never "off".
* **Reconcile loop** (`src/controller.ts`): every second `decideProgram`, then `SetCurrentProgramScene` only when the wanted scene differs from OBS's real program scene (tracked from events and verified every 3 s); reconciles after every (re)identify; never throws.
* **Audio** (`src/audio.ts`, `src/mic.ts`): millisecond ducking is OBS's (Compressor keyed to the mic, Noise Gate on the mic). The Companion checks the sources and filter exist (and whether the filter is keyed to the mic and the mic has a gate), applies the coarse policy of plan 9.4, toggles the ducking filter from Auto Duck (off = warning), fades with ~200 ms steps (about 5 requests a second of fade, never per word), uses play/pause only for a configured Media Source (otherwise Pause = Mute), and summarises the mic as quiet / speaking about once a second from meters (raw levels never leave).
* **Heartbeat** (`src/heartbeat.ts`): every 5 s, at most 4 KB, keys as in the contract (`obs_connected, obs_version, mode, on_air, fight, camera_off, camera_off_local, also_live, mapping_problems, music, controller_version, stale` plus a few small extras). No secret, scene list, path or raw level.
* **Local screen** (`src/ui/`): `http://127.0.0.1:4777` only. Peer must be loopback, Host must be 127.0.0.1 / localhost / [::1] on its own port (DNS rebinding), changes need `X-BOS-Companion: 1` + JSON + own Origin (cross-site forms/fetches). Lights (OBS, BuhurtOS, scenes), mode, on air and why, also-live with Take, a big local **CAMERA OFF** and a confirmed local clear, Take / Holding / Break / Return to Auto (local), music Auto / Mute / Pause and Resume (medical hold), scene test buttons, scene-mapping wizard, audio setup, credentials (write-only), log tail. Built with `textContent`, no external requests.
* **Credentials and files** (`src/credentials.ts`, `src/config.ts`, `src/log.ts`): Windows DPAPI (PowerShell, value on stdin), macOS Keychain (`security -i`, value on stdin), 0600 file fallback, read-only environment fallback. Settings and state in owner-only files written atomically. The logger redacts registered secrets (and variants), JWTs, Bearer headers, code-shaped strings, long secrets, and sensitive keys, in one place.

## 2. Behaviours a reader would otherwise have to guess

* **A hand switch in OBS is put back within about a second** (that is what "reconcile" means; Camera Off in particular must be). To take over by hand, quit the Companion (the stream carries on), or press a local Take. A "yield to hand" mode was considered and deliberately not built.
* **Local controls on the laptop** (Take, Holding, Break, music) are local manual choices that beat the server's AUTO/MANUAL until Return to Auto. Camera Off is separate (local latch, plus the server's).
* **No data yet = no decision.** From start until BuhurtOS has been read once, AUTO leaves OBS exactly as it is (a restart in the middle of a fight with no internet does not drop to holding). The decision memory is not kept either, so the first real decision is not delayed by the 10 s rule. Camera Off and manual choices still apply at once.
* **After a result the next fight on that Lyst is usually already called** (the queue advances on finalize), so the Lyst is "armed" and AUTO stays on it: "between fights" shows holding only when no fight is called on the Lyst. Armed Lysts are followed in the order they were first seen armed (kept in memory only: after a restart ties fall back to the priority list, then field key).
* **Medical hold.** Camera Off with reason `medical` mutes the music and sets a lock that survives release, restarts and OBS restarts. It is lifted by the local **Resume** button, or when the server's `music_mode` goes from muted/paused back to auto (set Muted, then Auto, in the Command Centre). Other reasons: music returns on its own after release. Camera Off never switches music on.
* **Silence is enforced continuously, sound only on a change**: an un-muted music source during a fight is muted again; a person's hand mute between fights is left alone until the state changes.
* **Missing mic** mutes the music (configurable); a missing ducking filter is reported but does not mute (plan 9 asks only for a report).
* **Camera Off scene missing**: holding is shown and the inputs listed in `audio.cameraAudioInputs` are muted (restored on release).
* **Unmapped Lyst already locked on**: the scene is kept (no action, reported); an unmapped Lyst that goes live is not taken at all.
* **Polling, not Realtime.** The reader polls (the plan allows "Realtime with polling fallback"); a controller token is not used for a socket.

## 3. How to run it
See `tools/obs-controller/README.md`. Short form: `cd tools/obs-controller && npm ci && npm run build`, then `start/start-broadcast.sh` (or the `.command` / `.bat`), open `http://127.0.0.1:4777`, paste the OBS password and the controller code, map the scenes.

Tests: `cd tools/obs-controller && npm test` (or `npx vitest run tools/obs-controller` from the root, which needs the root config to include `tools/**`; the suites that need the tool's own dependencies skip themselves, with a stated reason, when `npm ci` was not run there). Scenario: `PGHOST=/var/tmp/run PGPORT=55432 PGUSER=postgres POSTGREST_BIN=... scripts/e2e/obs-live.sh` (overridable `E2E_DB`, `REST_PORT`, `STACK_PORT`, `E2E_TMP`, `OBS_STANDIN_PORT`, `COMPANION_UI_PORT`).

## 5. NOT verified (do not claim otherwise)
* Anything on **real OBS**: the stand-in is written from the protocol documentation and may differ from real obs-websocket in response shapes, error codes, studio-mode behaviour, meter payloads, volume ranges, filter setting key names (`sidechain_source` etc.), and in what happens to the program scene when OBS restarts.
* Ducking depth/attack/release, pumping, noise gate behaviour, PA vs stream routing, cameras, the real overlay browser source on a scene, the 4455 firewall rule, a phone failing to reach 4455: all physical (plan 19). Not performed.
* Windows DPAPI via PowerShell, macOS Keychain via `security -i`, the `.bat` and `.command` launchers, a pinned-Node zip: written and unit-tested with a fake command runner only. Never run on Windows or macOS.
* Hosted Supabase: not touched. The hosted signing-key import, the custom roles and the Edge Function on hosted are the plan's owner steps (B2).
* The local screen was exercised in headless Chromium (render, big button, confirmed clear, no script errors, no sideways scroll on a 390 px window); not on a real laptop or tablet.
* Not built here: the Command Centre panels, the runbook `PACK181_EVENT_LAPTOP.md`, STATUS / PROJECT_SPEC entries.
