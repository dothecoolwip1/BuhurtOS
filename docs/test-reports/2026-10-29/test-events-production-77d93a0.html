## F1 — Misleading publication and statistics copy (P2)
Observed on actual test event: publish confirmation says Publishing makes the event, its competitions and registration public. Anyone can then register. Lifecycle says Current / Shown with current and upcoming events and Counts / Its official results count in rankings and statistics.
Signed-out URL and search correctly deny access. This is verified contradictory UI copy, not demonstrated public disclosure.
Source at 77d93a0: src/pages/SetupTab.tsx lines78–104; src/components/Lifecycle.tsx lines40–55. LiveEvent already exposes testDeleteAfter (src/data/api.ts line24).
Suggested implementation (not applied):
```tsx
const isTest = Boolean(event.testDeleteAfter);
// SetupTab publication heading and confirmation:
<h3>{published
  ? isTest ? 'Test event is published for its staff' : 'This event is public'
  : 'This event is a draft'}</h3>
<p>{isTest
  ? 'Publishing lets this event’s staff rehearse registration and scoring. It stays private, never counts in official records, and keeps its deletion deadline.'
  : 'Publishing makes the event, its competitions and registration public. Anyone can then register. You can take it back to draft, but people who registered keep their registration.'}</p>
// EventLifecycle: put this before normal archived/statistics branches.
{isTest ? <>
  <li><Chip>Staff only</Chip> Hidden from public event listings.</li>
  <li><Chip tone="live">Not counted</Chip> Test results never count in official statistics.</li>
</> : <>{/* existing normal-event visibility/statistics rows */}</>}
// Do not show restore/count-again controls on an immutable test event.
```
Reason: rendering must reflect test-event semantics rather than inferring visibility from published status or eligibility from statsExcludedAt alone. Keep backend guards; a wording fix must not relax permissions.
Regression: test and normal event fixtures, before/after publish and archive; test text never promises public access or rankings eligibility; normal text/actions unchanged.
